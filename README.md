## مواصفات السلوك التي حافظنا عليها

- حساب مجموع البنود من ضرب السعر بالكمية price \* qty.
- إذا تجاوز مجموع البنود 1000 يتم تطبيق خصم 5%، ثم تضاف ضريبة 15%.
- إذا كان المجموع يساوي 1000 بالضبط لا يطبق الخصم، ويكون الناتج النهائي 1150.00.
- طباعة الفاتورة بحيث تبدأ بكلمة INVOICE ثم تفاصيل البنود ثم TOTAL مع رقمين بعد الفاصلة.
- حفظ السجل بصيغة number;email;total داخل DATABASE أو FILES.
- عند استدعاء دالة sendEmail أو sendwhatsapp يتم طباعة الفاتورة ثم سطر الإرسال فقط، وترجع الدالة نص الرسالة بدون طباعته مرة ثانية.

## حساب LCOM1 للكلاس القديم

طبقنا القاعدة المطلوبة في الوظيفة: قمنا بعد أزواج الدوال التي لا تشترك في أي حقل كائن مباشر. لم ندخل الباني (constructor) أو دوال الـ getters أو الحقول الثابتة static في الحساب. لذلك الحقول التي اعتمدناها هي number و customerEmail و items فقط، واستبعدنا DATABASE و FILES لأنها static.

| الدالة         | الحقول التي تستخدمها مباشرة |
| -------------- | --------------------------- |
| addItem        | items                       |
| calculateTotal | items                       |
| printInvoice   | number, items               |
| saveToDatabase | number, customerEmail       |
| sendEmail      | number, customerEmail       |
| sendwhatsapp   | number                      |

لدينا 6 دوال تدخل في الحساب، وعدد الأزواج هو 6 \* 5 / 2 = 15 زوج:

| الزوج | الدالة الأولى  | الدالة الثانية | الحقل المشترك         | غير مترابط؟ |
| ----- | -------------- | -------------- | --------------------- | ----------- |
| 1     | addItem        | calculateTotal | items                 | لا          |
| 2     | addItem        | printInvoice   | items                 | لا          |
| 3     | addItem        | saveToDatabase | لا يوجد               | نعم         |
| 4     | addItem        | sendEmail      | لا يوجد               | نعم         |
| 5     | addItem        | sendwhatsapp   | لا يوجد               | نعم         |
| 6     | calculateTotal | printInvoice   | items                 | لا          |
| 7     | calculateTotal | saveToDatabase | لا يوجد               | نعم         |
| 8     | calculateTotal | sendEmail      | لا يوجد               | نعم         |
| 9     | calculateTotal | sendwhatsapp   | لا يوجد               | نعم         |
| 10    | printInvoice   | saveToDatabase | number                | لا          |
| 11    | printInvoice   | sendEmail      | number                | لا          |
| 12    | printInvoice   | sendwhatsapp   | number                | لا          |
| 13    | saveToDatabase | sendEmail      | number, customerEmail | لا          |
| 14    | saveToDatabase | sendwhatsapp   | number                | لا          |
| 15    | sendEmail      | sendwhatsapp   | number                | لا          |

عدد الأزواج غير المترابطة هو 6، وبالتالي قيمة LCOM1 = 6.

## التصميم بعد إعادة الهيكلة

- Invoice: يحفظ رقم الفاتورة وإيميل الزبون وقائمة البنود.
- InvoiceItem: يمثل بند واحد في الفاتورة مع الاسم والسعر والكمية.
- InvoiceCalculator: مسؤول عن حساب المجموع والخصم والضريبة.
- InvoiceFormatter: يجهز النصوص للطباعة أو الحفظ أو الإرسال، ولا يحتوي على حقول.
- InvoiceRepository: واجهة (interface) لحفظ الفاتورة، وينفذها الكلاسان DatabaseInvoiceRepository و FileInvoiceRepository.
- MessageSender: واجهة للإرسال، وينفذها الكلاسان EmailMessageSender و WhatsAppMessageSender.
- InvoiceService: ينسق العمليات بين الكلاسات السابقة (حساب، تنسيق، حفظ، إرسال) ويأخذ الكلاسات التي يحتاجها عن طريق الباني.
- Main: الكلاس الرئيسي لتشغيل البرنامج وتجربة الأمثلة.

استخدام الواجهات ساعدنا في فصل الكود، بحيث يعتمد InvoiceService على الواجهات بدلاً من الاعتماد المباشر على طريقة حفظ أو إرسال محددة.
